# Telegram MCP: инструкция с нуля

[English](START_HERE_EN.md) | [Русский](START_HERE_RU.md)

[Готовый промпт для ИИ-помощника](AGENT_SETUP_PROMPT_RU.md) · [README](../README.ru.md)

## Что вы получите

Ваш ИИ-помощник сможет читать доступные вашему Telegram-аккаунту облачные чаты, искать сообщения, готовить и отправлять сообщения и ответы. Это **не Telegram-бот**: действия выполняются от вашего аккаунта. Обычный BotFather-токен здесь не подходит.

Это ранняя beta. Проверены установка и автоматические тесты без настоящего аккаунта. Полный вход и работа в каждом ИИ-клиенте ещё не гарантированы. Секретные чаты, реакции, редактирование/удаление сообщений, отправка файлов и автоматическая расшифровка голосовых не поддерживаются. Вложения можно скачивать в пределах лимитов.

**Самый простой путь:** откройте промпт по ссылке выше, скопируйте его целиком в ИИ-агента, которому доступен терминал вашего компьютера, и отвечайте на вопросы. Обычный чат без инструментов сможет только объяснять действия. Вы по-прежнему сами вводите секреты и проходите вход.

## Перед началом: пять решений

1. Где будет работать программа: ваш Mac, Windows/Linux-компьютер или отдельный сервер? Компьютер должен оставаться включённым для постоянной работы.
2. В каком приложении вы будете обращаться к ИИ? Уточните точное название и версию. Оно должно поддерживать **удалённый MCP по HTTP с OAuth** или быть доверенным локальным клиентом, который запускает явный `--transport stdio`-режим. Нельзя просто добавить команду запуска в любое приложение и ожидать подключения.
3. Какой Telegram-аккаунт подключать? Лучше начать с отдельного тестового аккаунта. Один экземпляр сервиса рассчитан на одного владельца.
4. Есть ли у вас сервер, домен и HTTPS? Для облачного ИИ ваш endpoint должен быть доступен из интернета; `localhost` вашего ноутбука ему недоступен. Удалённый HTTP-режим требует HTTPS; доверенный локальный клиент может использовать stdio.
5. Нужны ли отправка и фоновый сбор? Отправку можно включить. Фоновый сбор сохраняет события и содержимое сообщений локально: до 30 дней / 100 000 событий. Доступ не ограничивается одним выбранным чатом.

Сам проект под MIT не требует покупки лицензии. Но сервер, домен, сетевой трафик и выбранный ИИ могут оплачиваться отдельно. Бесплатный тариф нельзя считать гарантией отсутствия счета. Перед созданием платного ресурса агент должен показать поставщика, актуальные условия, валюту, периодичность платежа и лимит, затем получить ваше согласие. Для теста сначала используйте уже имеющуюся инфраструктуру, если она подходит.

## Что нельзя отправлять агенту или публиковать

Не вставляйте в чат API hash, коды входа Telegram, пароль двухэтапной защиты, pairing password, OAuth-токены или содержимое `.session`. Не загружайте папку `runtime` в GitHub. Её содержимое включает доступ к аккаунту и личные сообщения.

Агент может подготовить установку и команды. Вход выполните **сами в приватном терминале**, не транслируемом агенту. Setup спросит номер/код и, если включена двухэтапная защита, пароль Telegram. Pairing password вводится в браузере только на вашем проверенном HTTPS-домене. Это отдельный придуманный вами пароль, не пароль Telegram. Если агент видит экран, приостановите его доступ на время ввода. В чат достаточно написать «вход завершён».

## Шаг 1. Скачать и установить

Нужны Git и Python 3.11 или новее. Агент может проверить их наличие. Не устанавливайте случайные сборки с посторонних сайтов.

**macOS / Linux**, обычный терминал, без `sudo`:

```sh
git clone https://github.com/t4god/telegram-personal-mcp.git
cd telegram-personal-mcp
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e .
export DOT_ROOT="$PWD/runtime"
```

**Windows PowerShell**: активация не требуется, поэтому менять Execution Policy не нужно.

```powershell
git clone https://github.com/t4god/telegram-personal-mcp.git
cd telegram-personal-mcp
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
$env:DOT_ROOT = Join-Path (Get-Location) 'runtime'
```

Ожидаемый результат: установка завершилась без ошибки. Не продолжайте автоматически после `ERROR`. Если папка уже существует, сначала выясните, что в ней находится; не удаляйте её и не клонируйте поверх действующей установки.

## Шаг 2. Создать собственное подключение Telegram

Вручную откройте https://my.telegram.org, войдите в свой аккаунт и создайте приложение в разделе API development tools. Получите **API ID** и **API hash**. Это не подписка на платный ИИ API и не токен бота. Доступность регистрации зависит от Telegram; агент не должен обходить проверки сервиса.

Запустите лично:

```sh
telegram-personal-mcp-setup
```

Для Windows:

```powershell
.\.venv\Scripts\telegram-personal-mcp-setup.exe
```

Программа спросит API ID, скрытый API hash и отдельный пароль подключения длиной минимум 20 символов, затем проведёт вход Telegram. В конце появится `Set DOT_OWNER_ID=...`. Сохраните показанное числовое значение для следующего шага. Pairing password запомните или сохраните в своём менеджере паролей.

Ожидаемый результат: сообщение `Setup complete`. Не пересылайте агенту полный вывод входа. Setup не перезаписывает существующую сессию. Если вход прервался и повторный запуск сообщает `Session already exists`, не удаляйте файл вслепую: используйте новую пустую папку через `--root` и задайте **тот же путь** в `DOT_ROOT` при запуске сервера. Неиспользуемую сессию можно завершить в настройках устройств Telegram.

## Шаг 3. Подготовить адрес HTTPS

Вам нужен собственный адрес, например `https://telegram.example.com`. **Это пример, а не работающий адрес проекта.** Подставьте ваш домен. За ним должен работать reverse proxy: программа, принимающая HTTPS и передающая запросы сервису на порту 8341.

Для агента или администратора:
- Настроить DNS и действительный сертификат для вашего домена.
- Проксировать весь сайт к сервису, а не только `/mcp`: OAuth discovery, авторизация и `/owner-login` тоже должны проходить.
- Сохранять внешний Host; `DOT_BASE_URL` должен точно совпадать со схемой и доменом, без `/mcp` в конце.
- Не открывать порт 8341 напрямую в интернет. Приложение слушает `0.0.0.0`; ограничение доступа обеспечивает сеть/контейнер/межсетевой экран. Изменения правил доступа сначала согласовать.
- Нельзя публиковать `runtime` как статические файлы сайта.

Если сервер и Caddy уже используются, после проверки конфликтов возможен такой блок конфигурации:

```caddyfile
telegram.example.com {
    reverse_proxy 127.0.0.1:8341
}
```

Он не заменяет настройку DNS, сертификата, портов и сервиса. Не перезаписывайте существующий proxy-конфиг. Если домена/HTTPS пока нет, остановитесь здесь и выберите вариант с агентом. Не отключайте проверку HTTPS ради быстрого запуска.

## Шаг 4. Запустить сервис

В том же терминале macOS/Linux с активированной `.venv`, подставив **свои** домен и числовой ID:

```sh
export DOT_BASE_URL='https://telegram.example.com'
export DOT_OWNER_ID='123456789'
export DOT_SEND_ENABLED=true
export DOT_BACKGROUND_MONITORING_ENABLED=true
telegram-personal-mcp
```

Windows PowerShell:

```powershell
$env:DOT_BASE_URL = 'https://telegram.example.com'
$env:DOT_OWNER_ID = '123456789'
$env:DOT_SEND_ENABLED = 'true'
$env:DOT_BACKGROUND_MONITORING_ENABLED = 'true'
.\.venv\Scripts\telegram-personal-mcp.exe
```

Если отправка пока не нужна, задайте `DOT_SEND_ENABLED=false`. Если не нужен фоновый сбор, задайте `DOT_BACKGROUND_MONITORING_ENABLED=false`. В `.env.example` есть образец, но программа **не загружает `.env` автоматически**. Экспортированные переменные действуют только в текущем терминале; автозапуск требует отдельно настроенной службы. Закрытие терминала может остановить процесс.

Сервис почти не пишет логи: отсутствие текста не означает зависание. После запуска проверьте ваш `https://ВАШ-ДОМЕН/health`: ожидается `{"ok":true}`. Это проверяет соединение, но ещё не подтверждает работу OAuth и отправки. Если ошибка содержит `Unexpected or unauthorized Telegram account`, проверьте соответствие ID и аккаунта; не отключайте эту проверку.

## Локальные stdio-клиенты

Orca и другие локальные клиенты, запускающие дочерний процесс, должны использовать явный stdio-режим вместо HTTP. Для draft-only интеграции оставьте `DOT_SEND_ENABLED=false` и не задавайте `DOT_BASE_URL` или webhook URL без отдельной необходимости:

~~~sh
PYTHONPATH=/path/to/telegram-orca-automatic-drafts/src DOT_ROOT=/path/to/private-runtime DOT_OWNER_ID=123456789 DOT_SEND_ENABLED=false DOT_BACKGROUND_MONITORING_ENABLED=false /path/to/.venv/bin/python -m telegram_dot.server --transport stdio
~~~

Процесс регистрирует те же MCP tools, включая `save_reply_draft`, `list_reply_drafts` и `get_reply_draft`, через stdin/stdout. Это локальная граница доверия, а не HTTP OAuth.

## Шаг 6. Подключить удалённый ИИ-клиент

Найдите в документации **вашего** приложения настройку удалённого MCP/OAuth. Имена меню меняются, а доступность зависит от клиента и тарифа. Адрес подключения: `https://ВАШ-ДОМЕН/mcp`.

Клиент должен открыть страницу авторизации на вашем домене. Введите лично pairing password из шага 2. Если увидели чужой домен или запрос прислать файл сессии в чат, остановитесь.

Встроены ограничения callbacks для ChatGPT и определённых локальных callback-адресов. Для других клиентов может потребоваться `DOT_OAUTH_REDIRECT_URIS`: список **точных HTTPS callback URL** из документации клиента, через запятую. Не добавляйте произвольные домены или wildcard. Эта настройка не добавляет поддержку push: webhook push сейчас ограничен OpenAI/ChatGPT callback hosts; другие клиенты могут использовать инструменты чтения по запросу. Даже для ChatGPT конкретный режим подключения должен быть проверен, а не обещан заранее.

Сначала попросите ИИ вызвать `connection_status` и `get_capabilities`. Далее выберите один разрешённый тестовый чат и прочитайте только согласованное сообщение. Не начинайте с массового сбора всех переписок.

## Шаг 7. Проверить сообщение без неприятных сюрпризов

1. Выберите безопасного получателя, например свои «Избранное». Агент должен определить настоящий chat ID, а не подставлять угаданный ID или неподдерживаемое имя `me`.
2. Согласуйте текст «Тест Telegram MCP» и получателя.
3. `prepare_send` создаёт черновик, **но не отправляет** его. Для повтора запроса используйте тот же `request_key`.
4. После вашего подтверждения агент вызывает `send_prepared_message` с точным получателем и текстом. Для ответа в переписке `reply_to_message_id` задаётся при подготовке черновика.
5. Успех: `status=sent`, `readback_verified=true` и сообщение действительно видно в Telegram. `uncertain` означает неопределённость: **не отправлять повторно автоматически**, сначала проверить чат.

Сервер проверяет совпадение черновика и ограничивает повторную отправку, но не может сам доказать, что человек дал согласие. Настройки подтверждений вашего ИИ-клиента важны. Не подключайте недоверенные приложения.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `command not found` | Активирована ли `.venv`; на Windows используйте полный путь `.exe` |
| `KeyError: DOT_BASE_URL` / `DOT_OWNER_ID` | Переменные заданы в том же процессе/терминале? |
| `HTTPS is required` | Указан реальный `https://` адрес, а не HTTP |
| Не найден pairing key / session | Совпадает ли `DOT_ROOT` между setup и запуском? |
| `Origin rejected` / callback rejected | Внешний домен, proxy Host и точный callback клиента |
| Sending is disabled | `DOT_SEND_ENABLED=true` в окружении запущенного процесса |
| Сессия занята / SQLite locked | Не запущен ли второй экземпляр с тем же runtime? |
| Health работает, ИИ не подключается | OAuth/HTTP совместимость клиента отдельно от Telegram-соединения |

Для помощи достаточно версии ОС/Python, шага, команды **без секретов** и текста ошибки с удалёнными личными данными. Не публикуйте базы, сессии и полные логи.

## Когда можно считать настройку законченной

Установка прошла, вход владельца завершён, HTTPS работает, клиент подключился через OAuth, разрешённое чтение проверено, и согласованный тест отправки подтверждён. Если проверено только что-то из этого, агент должен перечислить пройденные этапы и оставшиеся, а не писать «всё работает».
